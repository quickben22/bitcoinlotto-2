## 2. The release crash (main finding of the day)

### Symptom

APK installed from Google Play crashed immediately on launch. The same code built as a
debug APK worked, because debug is not minified.

### Evidence

Reproduced on an Android 15 emulator (`Pixel_5`, `emulator-5554`) with the v15 release APK:

```
FATAL EXCEPTION: main
java.lang.RuntimeException: Unable to get provider androidx.startup.InitializationProvider:
  androidx.startup.StartupException: java.lang.RuntimeException:
    Failed to create an instance of androidx.work.impl.WorkDatabase
  at androidx.work.impl.WorkManagerImpl.<init>
  at androidx.work.WorkManagerInitializer.create
```

Disassembling `classes.dex` with `dexdump` showed the generated Room class had **no
constructor at all**:

```
Class descriptor : 'Landroidx/work/impl/WorkDatabase_Impl;'
Direct methods   -          <-- empty, no <init>
```

Room instantiates the generated `*_Impl` database class **reflectively**, so a removed
constructor means a startup crash inside `InitializationProvider` before any Activity runs.

### Root cause

AdMob 25.5.0 pulled in `androidx.work:work-runtime:2.7.0`, which pulled in
`androidx.room:room-runtime:2.2.5`. That Room version ships this consumer rule:

```proguard
-keep class * extends androidx.room.RoomDatabase
```

It keeps the class *name* but not its members, so R8 was free to delete
`WorkDatabase_Impl()`.

### Fix (two steps)

1. **Immediate fix** — `app/proguard-rules.pro`:

   ```proguard
   -keep class * extends androidx.room.RoomDatabase { <init>(...); }
   ```

   Verified: `<init>` back in the dex, app launches.

2. **Proper fix** — upgrade the transitive WorkManager so Room carries the correct rule
   itself:

   - `gradle/libs.versions.toml`: `work = "2.12.0"`, alias `androidx-work-runtime`
   - `app/build.gradle.kts`: `implementation(libs.androidx.work.runtime)`
   - custom keep rule deleted (file back to just the header comment)

   Resolution after the upgrade:

   ```
   androidx.work:work-runtime:2.7.0 -> 2.12.0
   androidx.room:room-runtime:2.2.5  -> 2.7.0
   ```

   And `configuration.txt` now contains Room's own rule:

   ```proguard
   -keep class * extends androidx.room.RoomDatabase { void <init>(); }
   ```

   Re-verified: `WorkDatabase_Impl` has `<init>` in the release dex with **no custom rule**.

> All versions 13, 14 and 15 crash on Play. Version 16 is the first working release build.

## 3. Play Console rejection — foreground service

Commit `c130770` / `5d9b2ae` in `app/src/main/AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" tools:node="remove" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_SPECIAL_USE" tools:node="remove" />
```

plus removal of the library-provided `SystemForegroundService` component. The search is
visible-only (`VisibleSearchController` stops on `ON_STOP`), so no foreground service is
needed and the Play declaration no longer applies.

The merged release manifest was re-checked after all later changes:

```
FOREGROUND_SERVICE = False
FOREGROUND_SERVICE_SPECIAL_USE = False
SystemForegroundService = False
```

A unit test asserts the merged manifest contains no foreground work
(`app/src/test/kotlin/com/quickben22/bitcoinlotto/search/VisibleSearchControllerTest.kt`).

## 6. UI changes (`93fe3a4`)

- **Removed** the paragraph on the Stats screen ("Search runs only while the app is
  visible…") — `app/src/main/kotlin/com/quickben22/bitcoinlotto/feature/stats/StatsScreen.kt`.
  The `search_visible_only` string resource is kept: it is still used as the error message
  when `start()` is called while the app is not visible.
- **Smaller bottom banner** — `app/src/main/kotlin/com/quickben22/bitcoinlotto/ads/AdBanner.kt`:

  ```kotlin
  @Suppress("DEPRECATION")
  setAdSize(AdSize.getCurrentOrientationAnchoredAdaptiveBannerAdSize(context, widthDp))
  ```

  Standard anchored adaptive is 32–50 dp tall; the large variant (previous code) grows to
  ~90 dp. Play Services Ads 25.5.0 only offers the standard anchored API as deprecated —
  the non-deprecated ones are the "large" variants, hence the suppression plus comment.
  `remember` is keyed on `adUnitId, widthDp, orientation` so rotation re-sizes the view.
  `heightIn(min = 50.dp)` was kept deliberately: removing it made the slot collapse to
  0 px before an ad filled (verified with `uiautomator dump`).
